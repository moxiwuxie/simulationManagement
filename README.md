# 小店模拟器（Shop Simulator）

一个「真实开店」题材的经营模拟项目，包含两套可独立运行的部分：

- **Web 交互原型**：原生 HTML / CSS / JavaScript 单页应用，零构建、零 npm 依赖，打开浏览器即可玩。
- **Python 仿真内核**：无头经营仿真，负责程序化内容生成、顾客 Agent、议价、库存 FIFO、腐损、自适应定价、账务审计与长周期压测。

Web 端偏向「可操作、可观察、可决策」，Python 端偏向「可复现、可审计、可压测」。两端共享同一套经营直觉，但代码与存档彼此独立。

## 功能总览

### 1. 开店与空间

| 功能 | 说明 |
| --- | --- |
| 6 种店型 | 果蔬店、烧烤摊、蛋糕店、玉石店、沙县小吃、便利店，各自拥有独立商品目录与经营节奏；初始资金按成本定为 ¥1,800–¥3,500（果蔬 ¥2,000） |
| 启动资金 | 开局地图展示所选店型的启动资金，并说明含开业配货；配货只发放已解锁的基础菜品，余额留在现金 |
| 店名自定义 | 首次开店可输入 2–12 字店名，留空使用店型默认招牌；店名写入存档，并同步门头、顶栏品牌与页面标题 |
| 4 种铺面 | 摆摊（免租金）、小门面、大门店、一整层，租金、容量、员工上限逐级提升 |
| 7 个店址 | 老社区巷口、医院门口、菜市场、地铁口、大学城、写字楼、商圈，不同店址对早市 / 午间 / 晚市客流有差异化加成 |
| 店面可视化 | 货架、收银台、台秤、门头、顾客形象与到店动线，按真实店铺布局渲染 |
| 装修系统 | 地面 / 墙面 / 货架 / 灯光 / 保鲜 / 门头 6 类，每项包含材料、人工、工期、价格、质量、卖相加成、腐损系数、日常维护费、优缺点与安全隐患 |
| 装修收益 | 装修同时影响客流（毛坯约 −10%，满配约 +50%）、商品损耗（毛坯 ×1.12，满配约 ×0.76）、售价、口碑与意外风险 |
| 装修损益 | 累计记录一次性工程款、施工停业照付的租金与维护、停业少做营收、累计维护、意外赔付、装修原值 / 现值，并估算日增益、日净增益与静态回本天数 |
| 装修约束 | 施工占用天数、期间停业或不能摆货；施工日可点「跳过施工日」立即进入下一天，或等待 5 分钟自动进入，每天照付租金、工资与维护；劣质材料带来甲醛、滑倒、倾倒等风险，装修越差、耗损越重，每天出意外概率越高（毛坯最高约 18%/天，精装约 1.5%/天），事故会赔钱并扣口碑 |
| 装修折旧 | 耗损每日递增直接折价，全额支付日维护可小幅保养，翻新后耗损折半 |

### 2. 商品与库存

| 功能 | 说明 |
| --- | --- |
| 商品目录 | 果蔬店 6 大品类、71 种商品；烧烤摊 8 大品类（肉串 / 素串 / 海鲜 / 烤鱼 / 主食 / 凉菜 / 小吃 / 酒水）68 种；其他店型各有独立的面包 / 玉器 / 主食 / 零食目录 |
| 菜品分级 | 同一品类按进价分为基础 / 进阶 / 精品：基础开局可用；进阶需经营满 3 天且累计净利 ¥1,000；精品需 7 天且累计净利 ¥3,000。未解锁菜品在后台置灰并显示进度，禁止进货，自动补货与开局配货都会跳过 |
| 商品属性 | 进价、基准售价、保质期、货架容量、人气、单位、图标；单品可覆写每日损耗率 `decay` |
| 台面 / 后台库存 | 进货进入后台，必须在后台「上架」到台面才能售卖；两边各有容量上限。进货量只按后台剩余仓容计算，在途物流同样占用仓容；上架量取「后台库存」与「台面剩余容量」的较小值，台面放满后余货留在后台。支持「下架」把台面存货收回后台，受后台剩余仓容限制 |
| 台面 / 后台损耗 | 同一商品在台面与后台的腐损速率不同：普通店后台约为台面的 60%，烧烤后台冰箱 ×0.25、台面 ×1.6，蛋糕后台 ×0.55、台面 ×1.35，果蔬后台 ×0.7、台面 ×1.15；台面还会叠加货架/冷链系数。后台商品列表会直接标注两边当前日均损耗率 |
| 批次库存 | 按批次记录入库时间与成本，先进先出（FIFO）销售 |
| 补货上架 | 批量按钮严格按当前所选标签页执行：选「全部」覆盖全部商品，选单品类只处理该品类；「全部补货 / 本类补满」把每种已解锁商品补到后台仓容上限（受额度、现金与在途限制），「全部上架 / 本类上架」把每种商品后台存货补到台面容量上限 |
| 新鲜度与卖相 | 按单品损耗速率衰减（苹果慢、水蜜桃快），直接影响到店转化、议价空间与差评概率 |
| 时间损耗 | 每日按批次年龄与保质期加速扣减；过期日为标称保质期 + 最多 25%（不超过 3 天）的宽限，卖相好与洒水护理可小幅延长；烧烤后台冰箱 ×0.25，台面 ×1.6，没卖完的串损耗明显更高 |
| 损耗平衡 | 腐损按实际库存成本结算，过期后回收约 20% 残值；护理与装修减缓损耗，洒水次日生效 |
| 损耗归因 | 结算页给出损耗构成：主因品类占比、台面 / 后台占比、过期与自然衰减、平均库龄、理货与装修的降损效果；损耗率超过 5% 时高亮提示 |
| 商品维护 | 营业前可逐品或批量维护；营业中维护会占用 1 名空闲员工 |
| 缺货与腐损 | 缺货造成抱怨与流失；过期批次按残值计入损耗 |

### 3. 定价与促销

| 功能 | 说明 |
| --- | --- |
| 手工定价 | 按商品调整售价，受成本下限与市场上限约束 |
| 动态定价 | 基准价 × 季节系数 × 雨天敏感品类上浮 × 促销折扣 × 夜市清仓折扣 |
| 天气规则 | 果蔬店雨天叶菜 +30%，烧烤摊海鲜 +25%，蛋糕店面包 +10%，沙县主食 +10%，便利店零食 +8%；闷热天水果损耗翻倍，叶菜 / 凉菜 / 海鲜损耗 +35% |
| 四季循环 | 每 10 个游戏日轮换春 / 夏 / 秋 / 冬，顶栏显示季节进度；季节改变进价、损耗与品类需求（夏季生鲜损耗 +15%，冬季叶菜 / 海鲜涨价）；天气概率随季节变化，夏季多闷热暴雨，冬季几乎无闷热 |
| 三类供货商 | 散户批发进价 ×0.90、额度 ×1.35、损耗 +25% 且每批品质随机波动；本地农贸均衡；品牌冷链进价 ×1.14、额度 ×0.60、损耗 -40%、入库卖相更好；渠道只影响新批次 |
| 进货额度与物流 | 每日按商品给出到货额度，渠道额度不同；小额即时入库，单笔 ≥30 件走物流，下单即扣款、10–30 秒后到后台，后台在途可查；暴雨有 15% 概率少发约 20% 货量，物流也会延迟 |
| 晚市清仓 | 果蔬 / 蛋糕 / 沙县 / 便利店在晚市后半段按你设定的 5–9 折清仓，直到打烊；烧烤与玉石店不参与清仓 |
| 促销策略 | 全场折扣、满减、赠品等销售策略可与天气、季节、清仓叠加 |
| 水电杂费 | 每天固定扣除，随日租与铺面规模变化，计入结算净利 |
| 定价岗位 | 员工按「薄利多销 / 随行就市 / 精品高价」策略在开门前自动改价 |

### 4. 顾客与议价

| 功能 | 说明 |
| --- | --- |
| 顾客生成 | 年龄、家境、耐心、社交意愿、囤货倾向、性格标签组合出差异化顾客 |
| 12 类顾客 | 家庭主妇、上班族、学生、老顾客、美食博主、健身达人、环卫工人、警察、军人、中学生、阔太太、节俭老人，各有品类偏好与对话风格 |
| 到店行为 | 先按偏好挑选 3 个想逛的品类，再在品类内比价、挑拣；覆盖菌菇、葱姜等全部品类 |
| 售卖风格 | 果蔬散称多份（单菜多数量）；烧烤 / 沙县统一点单（2-3 样合成一单）；蛋糕 / 玉石 / 便利店单件成交 |
| 统一抹零 | 整单金额向下抹零：果蔬 / 烧烤 / 沙县抹到整元，蛋糕 / 便利店抹到整角，玉石不抹；抹零让利在结算单独列示 |
| 客单价自适应 | 价格印象、促销与欠费压力合成 ×0.80–×1.25 的客单系数，影响顾客一次购买的数量 |
| 议价 | 顾客可主动砍价；统一点单只对整单议一次价；店主可接受、拒绝、还价或保持沉默 |
| 讲价策略 | 可配置让价幅度与底线，支持「托管」自动处理议价 |
| 收银员代谈 | 在岗收银员可按讲价倾向代你与顾客谈价；倾向由性格、效率、心情与体力决定，倾向越高越敢守价磨价，也会提高手动讲价的成功率 |
| 自适应人流 | 全天分 5 个时段，结合店址、周末、天气、事件、员工叫卖、门店印象与昨日转化平滑调整（×0.85–×1.15） |
| 门店印象 | 货品卖相、服务分、价格印象、品类齐全度合成 ×0.80–×1.22 的客流系数；好货好服务次日客流上升，缺货差评则回落 |
| 顾客反馈 | 成交、拒绝、缺货、新鲜度共同影响评分与口碑 |

### 6. 分店与成长

| 功能 | 说明 |
| --- | --- |
| 分店 | 投入资金开设分店，按「保守 / 标准 / 激进」补货策略推算日利润 |
| 门店切换 | 顶栏「切换门店」可在总店与各分店间跳转；未选中的分店保持紧凑卡片，选中后展开控制台并定位 |
| 分店控制台 | 切换后展示近 7 日营收、累计净利、日均客流、营业天数与净利趋势柱；配置区可改名、装修升级、补货策略、员工与估值权重 |
| 分店升级 | 分店可升 3 级，每级日承载客流 +8%；费用按投入的 12% 计，计入投入与门店估值 |
| 分店歇业 | 可随时歇业止损：不进货、不发工资、不产生损耗，只付日租；恢复后重新进货 |
| 分店改名 | 分店支持自定义店名（最多 12 字），顶栏切换菜单与卡片标题同步显示 |
| 分店招人 | 招人预付 3 天工资，前 3 天日结不再重复计薪；离职时退还尚未消耗的预付工资 |
| 分店定价 | 切换分店后可设「薄利多销 / 随行就市 / 精品高价」定价策略，调价反向影响客流，直接影响日营收与净利 |
| 店长工资 | 员工卡片支持加薪 / 降薪，每次 ±10%，受底薪六折至三倍约束；加薪心情 +8，降薪心情 -12 |
| 店长代管 | 有在岗店长时可开启：自动按缺口进货、按基准价定价、把货补上台面，并在 4 秒后自动开门；营业中不能改薪 |
| 店长招人 | 店长会按收银 / 理货缺口自己物色人选，推荐进入「待老板审批」列表；同意即入职并当天计薪，驳回店长心情 -8 |
| 分店估值 | 每家分店有独立估值，每天随日利润、口碑与市场情绪浮动，可能增值也可能贬值；可自选波动权重（稳健 ±1.5% / 均衡 ±3% / 激进 ±6%） |
| 分店买卖 | 门店可按当前估值出售，扣 6% 转让税费后现金到账；低买高卖赚差价，高买低卖会亏 |
| 远程巡店 | 营业中也能查看分店日报与 7 日趋势、调补货策略、招人 / 辞退、改名、升级、歇业、改估值权重与出售；只有打烊结算时只读 |
| 新手目标 | 6 条目标：完成首日营业、单日净利 ¥300、口碑 4.0、雇佣 2 人、开出分店、累计卖出 100 件 |
| 成就 | 8 个成就：开业大吉、日进斗金、门庭若市、有口皆碑、人手齐备、开枝散叶、小有积蓄、百件达成 |
| 破产机制 | 连续 3 天以上付不起租金/工资/维护，或现金耗尽且无库存可卖时进入破产清算；展示最终资产、欠费与口碑，可重新开业 |
| 欠费预警 | 顶部显示欠费 N/3 天，流水记录当日资金缺口 |
| 中途退出 | 后台底部可主动退出经营：违约金按 30 天日租计算，库存按成本 50% 清算，分店按估值 70% 一并清算，结清后进入退租结算 |
| 退租计算 | 摆摊免租则违约金为 0；资产不足时以现有现金、库存与分店清算抵扣，差额不再追偿 |
| 趋势 | 记录每日营收、利润、客流、口碑，形成跨天走势 |
| 结算 | 日终结算展示营收、抹零让利、成本、损耗率、租金、装修维护、意外赔付、净利与资产变化 |
| 装修维护 | 日维护费随铺面规格放大，并叠加每日递增的装修耗损；翻新装修后耗损回落 |
| 客流数据 | 展示预测/实际到店、成交转化率、时段客流与营收、客流构成因子与门店经营评分 |
| 订单数据 | 展示订单数、件数、连带率、客单价、最高客单、议价成功率、热销 TOP3 |
| 补货目标 | 根据近期日销滚动计算补货量，避免按货架容量盲目囤货 |

### 7. 存档与体验

| 功能 | 说明 |
| --- | --- |
| 账号存档 | 支持注册 / 登录 / 退出，`shop.users.v1` 保存账号，存档按账号命名空间 `shop.sim.save.v1:<uid>` 隔离 |
| 游客模式 | 未登录可直接试玩，进度只保存在本机游客档（每台设备各自独立）；账号档与游客档严格隔离，账号档缺失时不会读取游客进度，游客进度也不会写入任何账号 |
| 后台清理 | 清理能力仅保留为后台运维函数 `wipeAllAccountData()` / `window.shopAdmin`：可删除全部账号、游客档、回退档与档案统计并保留音频等本地偏好；个人账号面板不提供该入口。另外每次数据换代（`shop.dataGen.v1` 标记）后首次启动会自动清空历史账号与存档 |
| 经营档案 | 账号面板展示当前存档的经营天数、最佳日净利、累计净利与成就数；不混入上一局或游客数据，重置后同步清空 |
| 营业中续接 | 营业中按顾客推进保存，关页后从当天营业进度继续，避免半天账丢失 |
| 存档容错 | 长线历史最多保留 180 天；遇到存储空间不足时自动压缩到最近 40 天重试一次，仍失败会在界面提示，避免静默丢档 |
| 存档备份 | 每天第一次保存时自动保留上一版存档；主档解析失败时回退到同账号备份，降低本地存储损坏导致的进度丢失 |
| 重置保护 | 重置时同时清掉主档与回退档，并抑制回写，避免旧存档或旧备份把新开局拉回上一局 |
| 开局初始化 | 新账号或重置后回到地图选铺面；历史、口碑（回到 3.2 基线）、评分、店名、员工、分店与账号档案全部归零，默认选中当前阶段可用的最小铺面 |
| 音频 | Web Audio 程序化 BGM、风声鸟鸣环境音、收银 / 议价 / 拒绝 / 开门 / 结算音效，可静音并记忆偏好 |
| 手机端 | 360–430px 可玩；营业中顾客面板改为底部操作台，后台全宽、标签自动换行，按钮加大触控区域 |
| 移动端信息 | 货架显示台面/后台紧凑库存徽标；流水收为最新一条，避免遮挡场景 |
| 响应式 | 桌面与移动端布局适配，无横向溢出 |
| 规则手册 | 内置玩法说明、员工说明、维护规则与数值提示 |

### 8. 阶段、货架与小店日常

| 功能 | 说明 |
| --- | --- |
| 经营阶段 | 四级关卡：路边摊 → 社区小店 → 精品生鲜 → 连锁经营，阶段只升不降，成长面板显示进度与下一阶段条件 |
| 阶段门禁 | 路边摊只能选摊位与果蔬 / 烧烤 / 沙县；社区小店解锁小门面、蛋糕店与便利店；精品生鲜解锁大门店、冷藏货架与分店；连锁解锁整层 |
| 货架分级 | 普通木架 → 精品货架（容量 +15%、购买意愿 +15%、台面损耗 -10%）→ 冷藏货架（容量 +30%、购买意愿 +20%、台面损耗 -50%），在装修页购买，只能逐级升级 |
| 小店日常 | 记录营业天数与 6 个里程碑（开张大吉 → 四季常客），展示每日手记与相册式回顾，不发放现金、不改变经济数值 |
| 温柔提示 | 根据昨日亏损、损耗、缺货生成一句轻建议（少摆台面、补货大方一点、先看租金），昨日摘要会跨天保留 |
| 阶段升级 | 达成新阶段时，结算页给出一次庆祝提示并写入流水；不额外发钱，只解锁对应铺面、店型与货架 |
| 暂不加入 | 广告、内购、排行榜等外部刺激会扰动调参，等核心循环数值稳定后再评估 |

> 设计取舍：货架分级、物流延迟 + 每日限购、阶段门禁负责「花钱换效率」与「堵住无限囤货」，是当前核心循环；正反馈只用里程碑与手记，避免外部奖励掩盖数值问题。

| 角色 | 日薪 | 默认能力 |
| --- | --- | --- |
| 收银员 | ¥60 | 缺货抱怨 -20% / 人，可代你讲价 |
| 店长 | ¥90 | 客流 +3% / 人，开门前自动维护 2 种货 |
| 理货员 | ¥50 | 腐损 -12% / 人，卖相 +1 / 天 |
| 叫卖员 | ¥55 | 客流 +8% / 人，顾客愿付 +5% / 人 |
| 采购员 | ¥60 | 开门前按策略自动补货下单 |
| 师傅 | ¥80 | 品控：卖相 +2 / 天，好评 +0.05 / 人 |

### 工资结算

员工工资按天折算：每天开门前自动从现金扣除当日工资，并计入当天经营成本；招聘当天立即计薪，员工页会显示当前日薪合计。现金不足时只支付部分工资，员工心情会下降。

### 体力与劳效

每位员工（包括第 1 号员工）都有 0–100 体力，不是永动机：

| 项目 | 消耗 / 规则 |
| --- | --- |
| 接待顾客 | 收银 1.1、叫卖 1.3、师傅 1.1、店长 / 理货 0.7、采购 / 定价 0.35 每人 |
| 营业中维护 | 16 体力，且体力低于 15 不能接维护 |
| 开门自动任务 | 采购员每单 6 + 2 / 种；定价员 10；店长维护 6 + 4 / 种；卖力吆喝 5 |
| 隔夜恢复 | `38 + 心情 × 0.15`，心情越好恢复越快 |

体力分档影响岗位效率：`≥60` 为 100%，`30–59` 为 85%，`10–29` 为 60%，`<10` 为 30% 且无法再接维护。连续加班会累积疲劳，员工页会显示体力条与「充沛 / 一般 / 疲惫 / 透支」状态。

### 可分配岗位（7 种）

员工入职后可以改派岗位，岗位决定实际加成，角色只决定底薪与默认岗位。

| 岗位 | 效果 |
| --- | --- |
| 收银 | 缺货抱怨 -20% / 人，可代你讲价（倾向随性格与状态变化） |
| 管理 | 客流 +3% / 人，开门前自动维护货品 |
| 理货 | 腐损 -12% / 人，卖相 +1 / 天 |
| 叫卖 | 客流 +8% / 人，顾客愿付 +5% / 人 |
| 采购 | 开门前按策略补货 |
| 定价 | 开门前按策略自动调价 |
| 品控 | 卖相 +2 / 天，好评 +0.05 / 人 |

### 岗位策略

| 岗位 | 策略 | 效果 |
| --- | --- | --- |
| 采购 | 少进快销 | 补最缺的 5 种，每种最多 18 件 |
| 采购 | 正常补货 | 补最缺的 9 种，每种最多 30 件 |
| 采购 | 备足货 | 补最缺的 14 种，每种最多 50 件 |
| 定价 | 薄利多销 | 基准价 92 折 |
| 定价 | 随行就市 | 维持基准价 |
| 定价 | 精品高价 | 基准价 +10% |
| 叫卖 | 温和吆喝 | 效果 70%，不扰民 |
| 叫卖 | 正常吆喝 | 效果 100% |
| 叫卖 | 卖力吆喝 | 效果 130%，员工心情 -3 / 天 |

采购补货受现金预算约束（最多使用约 60% 现金），并按「库存比例最低优先」挑选商品，避免一次性囤爆。进货先进入后台；采购员会自动把能摆的货补到台面。

### 性格（6 种）

勤快、老实、圆滑、爱摸鱼、乐观、脾气急。性格影响：

- **工作效率**：勤快 1.25、乐观 1.1、老实 / 脾气急 1.0、圆滑 0.95、爱摸鱼 0.7。
- **事件权重**：加薪、离职、摸鱼、专属事件的触发概率。
- **选项反应**：批准 / 拒绝加薪、训斥、无视等选择带来的心情变化。
- **专属事件**：主动挑烂货、多找零钱、旁敲侧击要福利、迟到、提议造气氛、与顾客争吵。
- **离职风险**：脾气急的员工在长期低心情下更容易辞职。

### 单任务占用规则

核心原则：**一名员工同一时间只能干一件事。**

- 营业中维护商品会占用 1 名空闲员工，持续 2 位顾客的接待时间。
- 被占用的员工不提供任何岗位加成，也不能收银。
- 正在接待顾客的收银员不会被抽去维护。
- 没有空闲员工时，店主自己上手维护，不阻塞营业。
- 占用结束后自动恢复岗位加成。
- 员工心情低于 30、请假、已处于占用状态或体力低于 15 时不会被安排新任务。

### 员工影响公式

设 `P(岗位)` 为在该岗位且状态正常的员工「性格效率 × 体力系数」之和：

```text
客流加成      = 8% × P(叫卖) × 吆喝策略倍率 + 3% × P(管理)
愿付加成      = 5% × P(叫卖) × 吆喝策略倍率
腐损系数      = 1 - 0.88 ^ P(理货)
每日卖相加成  = round(P(理货)) + round(P(品控) × 2)
缺货抱怨系数  = 1 - 0.8 ^ (P(收银) + 0.5 × P(管理))
店长自动维护  = round(P(管理) × 2) 种货
```

### 开门自动任务

每天开门前按顺序执行一次：

1. **采购员**按策略补货，写采购流水，消耗体力。
2. **定价员**按策略调整基准价，并夹在合法价格区间内，消耗体力。
3. **店长**自动维护卖相最差的商品，消耗体力。
4. **叫卖员**进入吆喝状态，「卖力吆喝」扣心情并额外消耗体力。

所有自动任务都会写入当日流水，便于对账与回看。体力不足 15 的员工会跳过采购、定价与店长维护。

## Python 仿真内核

### 程序化内容生成（PCG）

- 固定种子可复现：`random.Random(f"{seed}:day:{day}")`。
- 5 种天气：晴、多云、小雨、暴雨、闷热，各自影响客流与进价。
- 8 种事件：无、丰收季、运输受阻、周末集市、社区团购、网红探店、水果季、冷空气。
- 周末客流按店址差异调整：社区/菜市场上升，写字楼/大学城回落；事件可叠加品类供给系数。
- 每日生成各商品供给量，供需影响进货成功率与成本。

### 顾客 Agent

6 类顾客：家庭主妇、上班族、学生、老顾客、美食博主、健身达人。

- 预算、价格敏感度、耐心、社交意愿、囤货倾向、品类偏好。
- 最多逛 3 个货位，按偏好、价格与新鲜度筛选商品；临期批次会被挑剩下，越接近保质期越难卖出。
- 心理价随价格敏感度变化；议价需满足价格与耐心条件。
- 评价按成交价、成交数量、议价、缺货与拒绝综合计算，并回写口碑。

### 经济与库存

- 所有金额使用「分」的整数，避免浮点误差。
- 销售按批次 FIFO 扣减，库存不足抛 `InventoryError`。
- 补货受供给、现金、单品上限约束。
- 售价受成本下限与市场上限约束，并按行情与售罄率自适应调整。

### 对话

- 默认使用模板对话：问候、缺货、嫌贵、议价、成交、拒绝、感谢、评价。
- 可选接入 OpenAI 兼容 LLM：每天一次批量请求、最多改写 8 位顾客、预算可控、异常自动回退模板。
- `transport` 可注入，单元测试不访问真实网络。

### 账务审计

每日结算执行恒等式审计，违规码包括：

`LEAK`、`QTY_MISMATCH`、`LEDGER_MISMATCH`、`CASH_SPIKE`、`CASH_NEGATIVE`、`CASH_OVERFLOW`、`NEGATIVE_STOCK`、`LOT_OVERFLOW`、`INVALID_COST`、`PRICE_INVALID`、`REP_INVALID`、`OVERSOLD`。

任何违规都会进入报告；压测脚本发现违规时以退出码 1 结束。

### 通知

压测结束后可通过飞书 Webhook 推送摘要（仅标准库 `urllib`），推送失败不影响压测结果。

| 损耗率 | 5.3% | 0.2%–30% | 腐损 /（销货成本 + 腐损） |
| 成交率 | 97.9% | 40%–99% | 到店顾客中至少买走一件的比例 |
| 缺货率 | 0.233 | 0–0.9 | 每次到店的品类缺货报告次数 |
| 议价率 | 41.3% | 0–85% | 成交顾客中发生过议价的占比 |
| 口碑 | 3.41 | 1.8–5.0 | 期末口碑 |

任何一项中位数越界、或出现审计违规，`--check` 会以退出码 1 结束；报告同时输出每 30 天的资产倍数与净利率曲线，便于判断改动是「前期太苦」还是「后期通胀」。

## 规则与不变量

- 每日利润恒等式：`利润 = 营收 - 销货成本 - 腐损 - 租金`。
- 资产恒等式：`期末现金 + 库存账面价值 = 期初现金 + 营收 - 销货成本 - 腐损 - 租金`。
- 现金、库存、价格、口碑均有上下界，任何越界都会记录违规。
- 不允许负库存、超卖、批次数量溢出或凭空造钱。
- Web 端进货先取整单件成本再乘数量，确保现金减少额与库存账面价值完全一致；开局配货同样按真实进价入账。
- 资产 = 现金 + 货值（台面/后台/在途，按批次进价）+ 分店估值；售出时现金按实收售价增加、货值按所售批次进价减少，结算页与顶栏同一口径。
- 过期损耗按实际库存成本扣除，并回收约 20% 残值；残值计入现金与结算明细。
- 日常损耗按单品速率逐日扣减，批次越老损耗越快；仓储条件参与计算（烧烤冰箱后台 ×0.25、台面 ×1.6）。
- 统一抹零只向下让利，抹掉的零头不计入营收、不改变销货成本，因此资产恒等式仍成立。
- 客单系数限制在 ×0.80–×1.25，客流自适应限制在 ×0.85–×1.15，避免正反馈失控。
- 长周期压测必须保持非负现金、合法口碑、无违规。
- 经营必须有真实压力：一年内必须出现亏损日，同时禁止资产指数爆炸。
- 连续 3 天以上无法支付固定成本，或现金低于最低进货价且无库存，会触发破产清算。
- 主动退出经营时，违约金 = 30 天日租；库存按账面成本 50% 清算，差额不再追偿。
- 门店经营客流系数限制在 ×0.80–×1.22；服务分由评价、成交转化、缺货与拒绝滚动计算，单日不会暴涨暴跌。

## 已知边界

- **单账号单档**：每个账号一份存档（游客一份），不提供同账号多周目槽位；切换账号即可分开经营。
- **账号在本机**：用户名与密码散列只存 `localStorage`，没有服务端校验，清理浏览器数据会丢失账号。
- **营业中续接**：关页后从当天最近的营业进度继续，而不是回滚到当天早上。
- **分店为简化模型**：按投入、租金、口碑与补货策略推算日利润，暂未做真实排班与独立库存联动。
- **两端独立**：Web 原型与 Python 内核不共享运行时数据，规则与数值保持同一套经营直觉但并非逐行同构。
- **无后端**：Web 端所有状态在浏览器本地，LLM 与飞书能力只存在于 Python 侧。
- **LLM 默认关闭**：未配置密钥时完全使用模板对话，不产生网络请求。
- **金额单位**：内部统一使用「分」整数，展示时转换为元。
